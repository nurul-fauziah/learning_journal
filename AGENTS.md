# Workspace Rules: Frontend Design Standards (TasteSkill v2)

All web and frontend development in this workspace (templates, HTML, CSS, JavaScript, Jinja templates, UI components) must strictly adhere to the **TasteSkill v2 Anti-Slop** design standards.

The rules have been organized into 5 focused modular rule files under `.agents/rules/`:

1. **Strategy & Planning**:
   @.agents/rules/01-frontend-design-planning.md
   *Defines subject inventory, argument formulation, design direction, unique concept statement, and copywriting standards.*

2. **Execution & Quality Inspection**:
   @.agents/rules/02-frontend-execution-inspection.md
   *Enforces build order (tokens, hero, sections), imagery floors (minimum 4-12 real photos), zero-FAIL browser inspection, visual screenshot critique, and motion layers.*

3. **Strict House Rules (Anti-Slop Constraints)**:
   @.agents/rules/03-frontend-house-rules.md
   *Strictly prohibits generic aesthetic tropes: max 2-line headlines, no eyebrows/pill badges, no fake monospace/numbering, no gradients, no shadows at rest, no assistant palettes, no icon cards, no glassmorphism, and max 2 font families.*

4. **Laws of the Craft**:
   @.agents/rules/04-frontend-craft-laws.md
   *Quantitative typography ratios, spatial margins and section rhythms (120-240px gaps), color triad proportions (ground/ink/accent), authentic imagery rules, and minimal component styling.*

5. **Special Cases & Technical Reference**:
   @.agents/rules/05-frontend-special-cases.md
   *Procedures for existing brand systems, redesign/restyle workflows, software app screens (`data-ui`), offline/fallback handling, and reference directory index.*
